Angel Nexus Proxy Mutation Bug – Resolution Summary
Issue

Angel Nexus catalog operations worked through the LocalAI proxy, but mutation operations failed:

Operation	Direct Nexus (:8877)	Through LocalAI Proxy (:8080)GET /api/modules	✅	✅
POST /api/modules/install	✅	❌ 404 Module not found
POST /api/modules/add	✅	❌ 400 Bad Request

The browser, React frontend, and Nexus service were initially suspected.

Root Cause

The issue was isolated to the LocalAI proxy implementation in:

core/http/routes/angel_nexus.go


Diagnostic logging showed:

Incoming request:
Content-Length = 45

Outgoing proxied request:
Content-Length = 0


The proxy created the upstream request using:

http.NewRequestWithContext(
    ctx,
    c.Request().Method,
    targetURL,
    c.Request().Body,
)


but did not preserve the original request body's content length.

As a result, Angel Nexus received POST requests with an effectively empty body and failed module lookup/validation.

Fix

Added explicit content-length preservation:

// Preserve the incoming request body's known length. NewRequestWithContext
// cannot infer it from the incoming io.ReadCloser.
req.ContentLength = c.Request().ContentLength
